# Нормативные данные из Releases

PDF, нормативные SQLite и их выгрузки распространяются через GitHub Releases,
отдельно от исходников приложения. В Git остаются код, описание контрактов и
ограниченные тестовые фикстуры. Отчёты отдельных рабочих прогонов не являются
частью нормативного корпуса или входом модели.

`scripts/install-normative-data.py` собирает новую установку из двух выпусков:

- `normative-data-20261030`: каталог `base` и исходный комплект, включая электрику;
- `normative-data-20261105`: дорожный корпус `road-official-editions-20261105-v11`.

Имена архивов и SHA-256 закреплены в установщике. Сначала проверяются все
архивы; затем дорожный корпус подставляется внутрь новой временной установки.
Пути Compose сохраняются: `normative-handoff-20261030-092929/knowledge-base`.
Существующую установку скрипт не перезаписывает. Старые выпуски нужны для
проверок с сохранёнными нормативными pin и не должны удаляться при обновлении.

В дорожном архиве находятся выбранная SQLite, `CURRENT.json`, оригиналы её
источников и сведения об их происхождении. `RELEASE-MANIFEST.json` содержит
хеши файлов и известные пробелы. Наличие архива не подтверждает инженерную
корректность всего корпуса или применимость всех редакций.

Из домашнего комплекта не перенеслись два генерированных PDF-снимка сайта
производителя сеялки. Это не заводские PDF и не нормативы СП/ГОСТ/ГЭСН.
Исходные HTML сохранены и проверены по прежним SHA-256; отсутствие PDF явно
отражено в манифесте. Новые PDF под прежние хеши не создаются. Классификационные
данные производителя сами по себе не подтверждают нормативную применимость,
расход, конфигурацию машины или использование на объекте.

CI использует тот же установщик и `NORMATIVE_ROAD_KB_ROOT` / `NORMATIVE_KB_ROOT`,
что и обычная установка. Тесты не должны требовать пути домашнего компьютера.
