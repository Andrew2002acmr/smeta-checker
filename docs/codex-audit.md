# Экспериментальный аудит Codex Agent

## Адресные доказательства и зависимости ВОР

При поиске итога инструмент сопоставляет участок из названия таблицы, путь объединённых заголовков и единицу измерения. Для прочитанного числа сохраняются координаты ячейки, адрес строки, заголовки столбца и их геометрия. Воркер повторно проверяет число и адреса по закреплённой версии PDF. Подтверждение геометрии столбца помогает проверить принадлежность, которую устанавливает агент при сопоставлении ПД и ВОР.

При неоднозначности инструмент возвращает до 12 адресных кандидатов с общим числом совпадений. У найденной, но нечитаемой ячейки есть координаты для просмотра и причина `numeric_consensus_missing`. Ответ `not_found` означает, что путь к ячейке не найден в проверенной области. При исчерпании бюджета перечитывания заголовков возвращается отдельная причина. Отсутствие проектного основания устанавливается после исследования связанных источников.

Связи по формуле, соседству и контексту материалов передаются агенту вместе с адресами строк Excel. Явная формула устанавливает факт ссылки внутри ВОР. Инженерная связь проверяется по источникам и отражается в заключении по параметру. Совпадение величин и подсказки о материалах сами по себе не влияют на валидатор.

Для спорного заключения ведущий агент один раз сопоставляет конкретные источники и области применения. Отдельная роль проверяющего потребует сравнительного замера точности и стоимости. Повторная проверка от предыдущего запуска использует только подтверждённые адреса с совпадающими версиями ВОР, ПД и нормативов. При сбое до финального JSON промежуточные инженерные заключения теряются. Минимальный способ добавить восстановление — сохранять после технической валидации завершённую группу с перечнем строк, закреплёнными версиями, подтверждёнными доказательствами и открытыми вопросами. При продолжении использовать группы только с теми же версиями источников и протокола. Текущий кэш уже повторно использует извлечение из PDF по хешу оригинала и версии алгоритма.

Офлайн-проверка использует исходные PDF и Excel, а также JSON с ключами `cells` и `manual_review_links`. В `cells` передаётся `query` из страницы, участка, столбца и единицы, а также `expected_from_pdf` или `expected_status`. Связи задаются полями `row` и `parent`. Контрольные значения сравниваются после извлечения и не передаются поиску. Для холодного замера задайте пустой каталог кэша.

```sh
uv run python -m scripts.verify_codex_evidence --pdf project.pdf --workbook vor.xlsx \
  --baseline baseline.json --cache evidence-cache --output regression-report.json
```

### Диагностика сохранённой ВР-14

`scripts.diagnose_codex_audit` сопоставляет исходный ответ CLI, сохранённые заключения и журнал отклонений. Причины из текста заключения отражают сообщение агента. Технические отказы берутся из журнала валидатора. В исходном ВР-14 было 192 направления и ни одного отдельного `parameter_finding`. Все позиции уже имели открытый вопрос в направлении расчётов до валидации.

Четыре отклонения в строках 18, 20, 22 и 24 воспроизводятся на операндах с пробелом после десятичной запятой в адресной цитате. Исправлена интерпретация числа в цитате, которое backend отдельно проверяет по источнику. Арифметика и округление Decimal не изменены. В строке 58 фраза есть на физической стр. 74 нормативного PDF, но агент передал идентификатор с двумя пропущенными символами. Такой адрес по-прежнему отклоняется.

Для строк 41, 45, 49, 60 и 74 площадь и предельная толщина проверяются независимо от выбора машины. Сам типоразмер имеет значение для вывода о технологии. В закреплённом ПОС на стр. 85 указан второй типоразмер для дорог, а на стр. 86 — первый для пешеходных и велосипедных дорожек. Новый промпт просит отдельно указать роль вопроса. Агрегатор статусов и исторические выводы сохраняют прежние правила.

ВР-13: локальная полоса между физическими итогами и следующей группой столбцов восстанавливает пропущенную подпись участка. Повторное чтение заголовка маскирует рамку без удаления связанных с ней компонентов цифр. Отдельный тест перечитывает исходные фрагменты заголовков вторым OCR. Подтверждение числовой ячейки и геометрии остаётся отдельным измерением. При исчерпании бюджета возвращается `search_incomplete`.

Холодные регрессии дали 8 из 8 числовых ячеек ВР-14, 6 из 8 ВР-13, 2 из 4 на другом участке ВР-16 и 3 из 3 ВР-12. Второй OCR подтвердил область применимости у 4 из 8, 3 из 6, 2 из 2 и 2 из 3 прочитанных ячеек соответственно. Этот замер выполняется диагностически. Штатная проверка адреса сверяет геометрию и текст закэшированной структуры.

Живой пилот `109080fd-fdb6-4b1c-8629-62d71c81a891` проверил строки 18, 19, 41 и 62. В тестовой PostgreSQL сохранились четыре карточки и восемь дополнительных выводов. Числовые ссылки для 2689,14 м², 2648,61 м² и 91 м прошли техническую проверку. Три проектных вывода остались открытыми из-за отклонения ссылок на заголовки. Четыре ссылки содержали сокращённую цитату с адресом полного заголовка. Пятый заголовок не прошёл независимое перечитывание. Подсказка инструмента теперь явно указывает, как цитировать адресованный заголовок. Повторного модельного запуска для этой подсказки не было.

Обычный запуск использует существующий pipeline. В экспериментальном режиме API закрепляет версии ВОР, ПД и нормативных PDF и записывает задание в PostgreSQL. Хостовый воркер забирает задания Codex. Стандартная очередь Celery работает отдельно. Один запуск соответствует одной ведомости. При запуске комплекта создаётся запуск для каждой текущей ВОР.

Воркер вызывает установленный `codex exec` с JSON Schema и ждёт результат. Модель читает закреплённые оригиналы через локальный MCP. Инструменты дают текст, таблицы, изображения и OCR страниц по идентификаторам документов. Произвольные команды оболочки, подключённые приложения и плагины выключены. Данные, которые Codex выбирает для анализа, обрабатывает модель ChatGPT. В интерфейс и экспорт событий попадают инженерные выводы и безопасная телеметрия. Экспорт не содержит необработанного вывода CLI. Штатный Codex хранит свои сессии в закрытом каталоге пользователя воркера. Эти файлы могут содержать выдержки из документов, поэтому их срок хранения нужно настроить по правилам обработки проекта.

## Настройка на Ubuntu

Подготовьте отдельный стенд с веткой интеграции. Воркера запускайте от выделенного непривилегированного пользователя. Используйте Python из установленного backend-окружения проекта с полной группой зависимостей и Tesseract с языками `rus` и `eng`. В переменной `CODEX_AUDIT_CLI` можно задать абсолютный путь к установленному Codex CLI. Назначьте отдельный каталог `CODEX_HOME` с правами 0700 и войдите в ChatGPT через `codex login` от имени пользователя воркера. Воркер проверяет `codex login status`. Версия CLI должна поддерживать `exec --output-schema`, именованные профили доступа и функцию `multi_agent`.

API и воркер должны подключаться к одной PostgreSQL и к одному хранилищу оригиналов. Для Compose установите для тестового стенда публикацию PostgreSQL на loopback и примонтируйте каталог хранилища в контейнер API в `/srv/smeta/.audit_blobs`. Воркера на хосте подключите к этой БД через loopback и задайте `BLOB_STORE_URL=file:///абсолютный/путь/к/тому-же-каталогу`. У пользователя воркера должны быть права чтения оригиналов и записи артефактов. URL БД передаётся только доверенному Python-воркеру. Codex CLI получает отдельный список переменных окружения, в который URL и пароли БД не входят.

Для API задайте `CODEX_AUDIT_ENABLED=1`, `CODEX_AUDIT_NORMATIVE_DIR` и `CODEX_AUDIT_NORMATIVE_MANIFEST`. В Compose пути относятся к файловой системе API-контейнера. Например, укажите `/knowledge/road-norms` и абсолютный путь к `manifest.json` конкретного выпуска внутри этого каталога. В манифесте используются `sources[].blob_path` и `sources[].sha256`. Для изолированного теста вместо манифеста можно указать каталог с выбранными PDF. В каждом запуске сохраняется отпечаток всего набора источников. В повторной попытке используются сохранённые версии.

Электрический профиль использует `CODEX_AUDIT_ELECTRICAL_NORMATIVE_DIR` и `CODEX_AUDIT_ELECTRICAL_NORMATIVE_MANIFEST`. Отсутствующий или отличающийся по SHA-256 оригинал блокирует запуск с этим выпуском. В карточке одной ведомости поле «Первые позиции» задаёт объём пилота. Пустое поле запускает всю ведомость.

Если путь к манифесту не задан, API читает `CURRENT.json` в корне выбранной базы и закрепляет выпуск из указателя при создании запуска. У существующего запуска остаётся сохранённый отпечаток и набор оригиналов.

Для хостового воркера настройте следующие переменные окружения. Пароль БД храните в защищённом окружении службы.

```dotenv
CODEX_AUDIT_ENABLED=1
CODEX_AUDIT_CLI_HOME=/var/lib/smeta-codex/cli
CODEX_AUDIT_TIMEOUT_SECONDS=2700
CODEX_AUDIT_DOCUMENT_CACHE_DIR=/var/cache/smeta-codex/documents
```

Каталог кэша создаётся от имени воркера. Он хранит текст страниц, структуру таблиц и распознанные ячейки, поэтому выдайте доступ только пользователю воркера. При отсутствии настройки кэш живёт до конца задания. Ключи содержат SHA‑256 оригинала и версию формата или алгоритма. Для каждого заключения воркер сохраняет свои адресные наблюдения и самостоятельно проверяет ссылки. Очистка кэша не влияет на сохранённые карточки.

Модель можно закрепить через `CODEX_AUDIT_MODEL`. Для сравнения режимов задайте одну и ту же модель. Включайте `CODEX_AUDIT_ALLOW_CHATGPT_DOCUMENTS=true` в окружении воркера только после согласования отправки выбранных документов в ChatGPT. По умолчанию обработка документов через CLI выключена.

Для оценки расхода можно задать `CODEX_AUDIT_MONTHLY_QUOTA_REFERENCE_USD=107`. Расчёт делит месячный ориентир на четыре недельных окна. При прямой настройке недельного ориентира используйте `CODEX_AUDIT_WEEKLY_QUOTA_REFERENCE_USD=26.75`. В `metrics.json` поле `chatgpt_quota` содержит снимки до и после работы Codex, разницу использования квоты в процентных пунктах и уменьшение баланса кредитов, когда сервис возвращает баланс. При смене окна или стартовом значении 100% оценка отсутствует. Снимки относятся ко всему аккаунту. Для привязки расхода к запуску исключите параллельное использование того же аккаунта. Токены главного агента находятся в `main_agent_tokens`, токены субагентов — в `subagents[].tokens`.

Из каталога `backend` запустите хостовый воркер:

```bash
uv run python -m scripts.codex_worker
```

Откройте новую проверку через обычный интерфейс и выберите Codex Agent. Отмена останавливает дочерний процесс. При потере воркера задание получает завершённый статус после окончания аренды. Повторный запуск выполняет анализ заново на тех же версиях документов.

Во время выполнения показываются стадия, длительность и наблюдаемое число вызовов инструментов. Заключения проверяются и публикуются после получения структурированного ответа на ведомость. Процент готовых строк внутри текущего ответа модели неизвестен.

## Проверка и сравнение

В результате доступны три независимых вывода, ссылки на физические страницы оригиналов, арифметика и раздел «Производительность». Скачайте `metrics.json`, `performance_report.md`, `audit_results.json` и `execution_events.jsonl` со страницы запуска.

В каждом направлении можно сохранить несколько проверок параметров. Например, площадь показывается с её статусом и двумя ссылками, а подтверждение технологии устройства отображается рядом как отдельный вопрос. Итог позиции сохраняет приоритет доказанного расхождения. Если Codex пропустил строку, проверенные строки сохраняются, а пропущенная отображается как «Не проверено» и учитывается отдельно в метриках. Для расчёта по ПД хотя бы один операнд должен иметь ссылку на ПД. Цитаты и арифметика проверяются по каждому параметру независимо.

Кнопка «Уточнить этот параметр» открывается для вывода, где требуется основание. Запишите документ, страницу или пояснение. Система создаёт отдельный запуск для этой позиции с прежними закреплёнными оригиналами и предыдущими выводами. Повтор одинаковой отправки возвращает тот же запуск. Для пилотного коэффициента 1,26 сохранён отдельный сценарий с выбором связанных строк в той же конструкции.

Адресная проверка поддерживает текстовые ячейки, растровые таблицы и отдельные надписи чертежа. В растровых таблицах сохраняются физические границы ячейки и относящиеся к ней заголовки. Для чертежа локальное распознавание создаёт ссылку, когда два прохода OCR дают одну и ту же короткую надпись. Связь выноски с конструкцией проверяет агент по чертежу. Локальный тест на стр. 76 подтвердил надпись «проезжая часть», а неустойчиво прочитанные размеры не получили ссылку.

Для сравнения запускайте один ВОР с субагентами и без них, сохраняя версии всех исходников, модель и условия эксперимента. Среднее на позицию делит время ведомости на число позиций. Медиана и перцентили индивидуальных длительностей отсутствуют, когда время измерено только для ведомости. Недоступные показатели имеют значение `null`. Данные об использовании подписки зависят от CLI и аккаунта. Достоверность оценивается по независимой выборке с оригинальными источниками.

Для ВР-12 по оригиналам проверьте выборку подтверждений и расхождений. Сравнение запуска с субагентами и одиночного запуска проводите после проверки качества на одинаковом комплекте закреплённых источников.
