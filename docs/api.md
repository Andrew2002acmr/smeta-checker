# REST API

API обслуживает Nuxt через серверный BFF; браузеру API-токен не передаётся. Состав маршрутов и схемы запросов текущей версии доступны в OpenAPI работающего API (`/docs`, `/openapi.json`); исходные определения находятся в `backend/api.py` и `backend/workspace_api.py`. Ниже — основные операции, а не полный контракт.

## Доступ и безопасность

В Compose `AUDIT_API_TOKEN` обязателен; запросы к `/api/v1/*` передают заголовок `Authorization: Bearer <AUDIT_API_TOKEN>`. Храните токен только в серверном окружении, не в `NUXT_PUBLIC_*` и не в браузере. `/healthz` доступен без токена. Пустой токен в конфигурациях вне Compose отключает эту защиту и не подходит для рабочего сервера.

**API-порт в текущем `compose.yaml` опубликован как `${API_PORT:-8000}:8000` без адреса привязки**, в отличие от workspace с `WORKSPACE_BIND=127.0.0.1` по умолчанию. Ограничьте доступ к API сетевым экраном; не открывайте его в интернет. Для внешнего workspace используйте HTTPS reverse proxy и необходимые ограничения сети; настройка входа и AD приведена в [инструкции запуска](docker-quickstart.md).

Имена загрузок и содержимое проверяются до разбора; ограничения размера и количества задаются `AUDIT_MAX_UPLOAD_BYTES` и `AUDIT_MAX_UPLOADS_PER_REQUEST`. Для передачи документов внешней LLM или телеметрии требуется разрешение на передачу данных соответствующему сервису; подробнее — [мониторинг](monitoring.md).

## Основной цикл

1. `POST /api/v1/projects` создаёт проект. Для работы с документами используйте его UUID.
2. `POST /api/v1/documents` принимает multipart: `project_id`, `kind=vor|pdf`, `file`, а также явное назначение `new_document=true` для нового документа либо `document_id` для новой редакции. Ответ содержит UUID документа и редакции, номер редакции, SHA-256 и размер.
3. `POST /api/v1/documents/preflight` принимает `project_id`, `vor_version_id` и `pdf_version_ids`; возвращает строки предварительной проверки и `has_critical_error`. Версии должны принадлежать проекту.
4. `POST /api/v1/audits` принимает те же идентификаторы и возвращает HTTP 202 с `run_id` и начальным статусом. Проверка асинхронна; выбранные редакции фиксируются в запуске.
5. `GET /api/v1/audits/{run_id}` возвращает состояние, `GET /api/v1/audits/{run_id}/results` — итоговые результаты, `GET /api/v1/audits/{run_id}/reports/word` — Word-отчёт. До завершения итоговые результаты и отчёт отвечают 409 `audit_not_finished`; для поэтапного просмотра есть отдельные маршруты workspace, см. [поэтапную проверку](progressive-review.md). Excel-отчёт аудита не поддерживается.

Проверка и передача в очереди описаны в [resumable-audits.md](resumable-audits.md); выбранные пользователем основания — в [human-evidence.md](human-evidence.md). Структурированные ошибки API содержат `error.code`, `error.message` и, при наличии, `error.details`. Нет хранилища — 503 `storage_not_configured`, нет настроенного ключа модели — 503 `llm_not_configured`, нет токена при включённой защите — 401 `unauthorized`. Доступность маршрута не доказывает корректность результатов модели: пользователь должен проверить основания и цитаты.
