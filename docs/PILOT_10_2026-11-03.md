- Использованы существующие реестр фактов, связи работ, планирование и follow-up. Уточнены роли источников, независимые аспекты, поиск полного контекста и различие unit / unit_scale.

## Уточнение причины RouterAI — 03.11.2026, 21:23:53 (Новосибирск)

По отдельному запросу пользователя выполнена одна диагностическая отправка того же сохранённого шага `request-03.json` к той же модели. HTTP-клиент без автоматических повторов. Тело ошибки сохранено с маскированием секретов, заголовки — по разрешённому списку.

Ответ провайдера:

```json
{"status":429,"error":{"message":"API key monthly spending limit exceeded: 1 000,36 руб. / 1 000,00 руб.","code":429}}
```

Это действующее ограничение **месячных расходов API-ключа**, а не доказанный лимит частоты, токенов или недостаточный общий баланс аккаунта. Лимит превышен на 0,36 руб. На диагностическом запросе ограничение не снято. `Retry-After` и `x-ratelimit-*` в ответе отсутствуют. Пауза между запросами не устраняет причину, указанную провайдером.

[Точный безопасный ответ и заголовки](evidence/routerai-diagnostic-response.json). Справка RouterAI также различает ошибку `API key monthly spending limit exceeded` и нехватку баланса: https://routerai.ru/docs/guides/mcp/connect . Ответ нашего API является непосредственным доказательством, документация — пояснением смысла сообщения.

Ретроспективная граница: тела 28 старых ошибок не сохранялись, поэтому их посимвольное совпадение с новым ответом недоказуемо. Однако воспроизведение того же неудачного шага тем же ключом однозначно показывает текущий блокер и основание не повторять пилот.

Бюджет пользовательского разрешения учитывается консервативно по попыткам, независимо от тарификации: предыдущий пилот 30 + диагностика 1 = 31 из 60; остаток не более 29. Локальные неудачные запуски диагностического скрипта до установления сетевого соединения не являлись отправками модели. Исходные baseline 52 вызова относятся к историческому прогону, вне этого разрешения. Денежная сумма 1 000,36 руб. относится к месячному счётчику ключа, её нельзя приписывать одному нашему пилоту.

Повторный пилот **не запускался**, поскольку условие пользователя «если ограничение уже снято» не выполнено. Лимит ключа, платёжные настройки и ключ не изменялись. Рабочая PostgreSQL, активный нормативный выпуск и все 103 позиции не затронуты. Предыдущее сравнение с baseline остаётся без изменений: новой завершённой проверки нет. Для продолжения нужно снять месячный блокер; автоматическое увеличение лимита или смена ключа не выполнялись.


## Локальные исправления после запрета модельных вызовов

Новых обращений к RouterAI не выполнялось; остаток общего лимита попыток не изменён. Baseline и неуспешный live-пилот не переписаны, свежие содержательные статусы не заявляются.

1. В существующем адаптере `normative_context` добавлена обработка воспроизведённого сообщения `API key monthly spending limit exceeded:` при коде 429 — как для HTTP-ошибки SDK, так и для error envelope внутри HTTP 200. Диагностика содержит только фиксированную причину `api_key_monthly_spending_limit_exceeded`, код и `retryable=false`; произвольные тела ответа, финансовые суммы, ключи и тексты документов не публикуются.
2. Такая ошибка останавливает повторы **внутри текущей агентной проверки** и остаётся `technical_failure`, без инженерных карточек отсутствующих фактов и без замечания к ВОР. Неизвестный 429 сохраняет прежний ограниченный механизм повторов. Новый глобальный диспетчер/автоматический повтор пакета не создавался.
3. В добавленной строгой политике коэффициентов тестом воспроизведён пропуск: при отсутствии карточки коэффициента модельный `confirmed` зависимого расхода мог сохраниться. Теперь для явно названного множителя произведения требуется подтверждённая карточка того же значения со ссылкой на источник; отсутствие карточки не считается доказательством.
4. Вторым тестом воспроизведено снятие независимых подтверждений при объединённом item: неизвестный коэффициент переводил в `needs_facts` сразу площадь, толщину и расход. Теперь выделяется только `derived:rate`; исходные подтверждения остальных claims сохраняются. Исходный модельный item записывается в trace. Проверка доказательств не ослаблена, новые подтверждения не создаются.

Локальная целостность проверена для всех 10 оригинальных снимков: SHA, схема ответа, уникальность source IDs, завершённость запросов чтения, принадлежность ссылок версии ПД. Также повторно сверены SHA оригинальных ВОР и ПД, PDF ГОСТ и подготовленного нормативного выпуска. Чужих версий ПД и повреждений не обнаружено. Сохранённый ответ index=3 содержит одну известную некорректную ссылку — пустой `source_id` у коэффициента 1,26, несмотря на модельный `scope_state=verified`. Архив точно сохраняет этот недостаток; это не доказательство коэффициента. [Результат проверки целостности](evidence/offline-evidence-audit.json).

Регрессии: **227 passed**, без пропусков, в контейнерах без внешней сети и с отдельной временной PostgreSQL. Проверены отказы провайдера, строгие коэффициенты, независимые факты, сохранённые доказательства, подготовка PDF/нормативов, упаковка контекста и итоговые вердикты. Первоначальные ошибки расширенного запуска были ограничениями тестового окружения (не настроена тестовая БД / read-only cache); после изоляции БД и выделения cache в tmpfs тот же набор прошёл. Ruff для изменённых файлов и настроенный pyright с явным Python из venv прошли. [Машинный результат регрессий и SHA кода](evidence/local-regression-results.json).

Это локальная проверка исправлений, не новый модельный пилот и не замер роста confirmed. Нерешёнными остаются инженерная привязка среднего слоя к нормативной ветви, основания коэффициентов/расхода/плотности и доказательство совместимости характеристик материала. Составной legacy claim не подтверждается целиком по доказательству только его проектной части. После снятия блокера понадобится отдельный свежий пилот тем же набором; все 103 позиции не запускались.
