# Основания, выбранные пользователем

В сверке позиции ВОР доступны два действия:

- «Подтвердить основание» сохраняет выбранную автоматическую цитату.
- «Указать основание» открывает три режима: «Строка таблицы» (нажатие внутри
  строки), «Область» (рамка мышью), «Текст» (обычное выделение мышью с
  автоматическим предпросмотром после отпускания кнопки).

Перед сохранением показывается точная серверная цитата и подсветка. Для строки
используются границы её физических ячеек; для области — центры символов,
для текста — отдельные фрагменты выделения, без объединения в общую рамку.
Это исключает попадание соседней строки только из-за пересечения верхушек букв.
Если строка таблицы не определяется, интерфейс предлагает область или текст.
Для скана область сохраняется и без текстового слоя. Старые сохранённые выборы
не переписываются: неверный выбор нужно отменить и указать заново.

Выбор отображается в разделе «Выбор пользователя». «Показать в PDF» открывает
нужную страницу и подсвечивает область. Подтверждение можно отменить.
Отмена сохраняет автора и время в истории базы, а не удаляет запись.

## Хранение и повторное использование

Миграция `0007_human_basis` добавляет таблицу `human_basis`. Запись содержит
проект, запуск, позицию, версии ВОР и PDF, страницу, координаты, цитату,
комментарий, автора, время и происхождение выбора. Автор веб-действия поступает
из проверенной серверной сессии, а не из формы браузера.

При повторной проверке той же версии ВОР и PDF выбранные основания показываются
с отметкой «Выбрано в предыдущей проверке этих же документов». Ключ позиции
учитывает исходный лист/строку и содержательные поля; номера A/J не считаются
инженерным подтверждением. Изменённая версия PDF и другая позиция не наследуют
выбор автоматически.

Автоматический результат не переписывается, выбор человека хранится отдельно.
Данные доступны через API для последующего использования в поиске, оценке
качества и подготовке обучающей выборки. Автоматическое обучение модели и
перенос подтверждений на другие проекты в эту реализацию не входят.

## API

Префикс: `/api/v1/audits/{run_id}/positions/{position_index}/basis`.

- GET — список действующих оснований, включая применимые из предыдущих запусков.
- POST `/confirm` — подтверждение цитаты по `evidence_index`.
- POST `/preview` — предпросмотр: `version_id`, `page`, `rect`, `mode`
  (`row`, `area`, `text`), для текста также отдельные нормализованные `rects`.
- POST — сохранение того же выбора с `comment` и `selection_digest` из
  предпросмотра. Несовпадение предпросмотра отклоняется; цитата извлекается
  сервером из исходного PDF, а не принимается из браузера.
- DELETE `/{basis_id}` — отмена подтверждения с сохранением истории.

Требуется штатная авторизация. Сервер проверяет наличие позиции, принадлежность
версии проекту, включение PDF в запуск, номер страницы и координаты области.

## Обновление

Обновляйте API и интерфейс вместе. Перед запуском нового API примените миграцию
тем же актуальным образом `migrate`, который собран из этой версии исходников.
При использовании локального стенда передавайте `.env.local`, оба compose-файла
и имя проекта `smeta-checker-local` во всех командах Docker Compose.

Проверки: `tests/test_human_basis.py` и `frontend/tests/e2e/human-basis.spec.ts`.
Браузерные проверки используют отдельную БД и синтетические документы без
обращения к модели. Изменение интерфейса выполнено без pen.dev по прямому
согласованию пользователя в этой задаче.


## Несколько областей и распознавание

Режим «Несколько областей» накапливает до 20 рамок на разных страницах одного
PDF в одном основании. Каждую рамку можно удалить, назначить ей роль и перейти
на её страницу. Смена PDF, позиции или отмена очищает несохранённый выбор.

«Распознать выбранное» запускает локальный Tesseract только для рамок (rus+eng,
PSM 6), без LLM. Ограничения: до 4 Мп на изображение, до 3000 px по стороне,
до 10 секунд на проход и общий бюджет 70 секунд; одновременно до двух OCR
запросов на процесс API. Кнопка также доступна для одиночного выделения.

Текст можно исправить вручную. Исходный OCR, исправление, признак проверки текста,
назначение, координаты и изображения фрагментов сохраняются отдельно в payload
human_basis. OCR-результат хранится в серверном blob store и связан с версиями
и точным набором рамок; изменение геометрии требует повторного OCR. При сохранении
OCR не запускается снова. Подтверждение основания не означает проверки текста.
Автоматическое обучение не запускается. Изображения доступны для будущего экспорта.

POST /basis/recognize принимает тот же SpecifyBasisRequest с mode=multi и
fragments=[{page, rect, corrected_text?, text_checked?, role?}]. Возвращает
предпросмотр и ocr_key. Сохранение принимает ocr_key и фрагменты с исправлениями.
Без OCR можно сохранить рамки и самостоятельно введённый текст. Миграция не нужна.
