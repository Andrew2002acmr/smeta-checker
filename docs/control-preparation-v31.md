# Подготовка контрольного запуска после переноса

Восстановленные заключения и новый ответ модели проверяются отдельно. Выборка из
20 позиций служит регрессией на известном объекте, не независимым испытанием качества.

1. `python -m scripts.reprepare_document --version-id UUID --template-run UUID --out DIR`
   готовит PDF целиком и сохраняет native/OCR, таблицы, ячейки и координаты. Контрольная
   точка `progress.json` записывается после каждой страницы. Повтор команды продолжает
   работу. Проверки позиций и платные запросы не запускаются.
2. Если таблицы завершились технической ошибкой, повтор той же команды с
   `--retry-failed` перечитывает только ошибочные страницы. Сохраняются предыдущие
   ссылки на страницы. Распознаватель таблиц повторяется только после таймаута:
   первоначальный бюджет 90 секунд, один повтор 180 секунд. Повторный сбой не
   превращается в пустую таблицу или успешную подготовку.
3. `report.json` должен содержать `ready: true`, нулевую очередь OCR и отсутствие
   ошибок страниц. Снимок проверяется повторным чтением из blob-хранилища и
   регистрируется в версионированном кэше подготовки. Старые запуски не переписываются.
4. `python -m scripts.prepare_agent_control --matching-run UUID --preparation DIR
   --normative-root DIR --normative-database releases/RELEASE/knowledge.sqlite
   --normative-sha256 SHA --indices ... --out PLAN.json` связывает сохранённое
   сопоставление и новый подготовленный ПД по хешам/версиям. Весь контекст ВОР,
   включая невыбранные связанные работы, остаётся доступен. Нормативный выпуск
   закрепляется только для контрольного запуска; глобальный CURRENT не меняется.

План содержит `normative_fresh_model: true`: предыдущие конечные ответы не должны
подставляться вместо ответа модели. При этом разрешено повторно использовать
подготовку OCR и подтверждённые исходные факты с их происхождением. Ожидаемые
статусы из домашнего реестра не являются входом модели. Выдача остаётся порциями
по 10 позиций. До отправки запросов отдельно задаётся согласованный бюджет вызовов.

Это подготовка к проверке, а не обещание двадцати подтверждений. Применимость
редакции нормативов и выявленные противоречия должны сохраняться в итогах.

Чертежи учитываются отдельно: таймаут таблицы на явно озаглавленном продольном/
поперечном профиле или плане маршрутизируется в `drawing_analysis_pending`.
Исходная техническая ошибка не удаляется. Страница с ведомостью объёмов,
спецификацией или заголовками «Наименование / Количество» не обходится этим
правилом. Модель получает отдельный список таких листов в coverage; отсутствие
доказательства на неразобранном чертеже не доказывает расхождение ВОР.
