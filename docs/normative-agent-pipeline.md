# Автоматический нормативный этап

## Версия 6: независимые факты и ограниченный дополнительный поиск

Первичная проверка сохраняет отдельные утверждения о количестве, геометрии,
нормативной применимости и расходе. Неизвестное нормативное условие не отменяет
буквально подтверждённую площадь. При этом исходное `needs_facts` модели не
превращается в подтверждение: разделение утверждений сохраняет её состояние.
В числовой карточке сначала разделяются размерности: площадь и объём не являются
двумя конкурирующими площадями. Разные площади по-прежнему требуют разрешения
неоднозначности. Сравнение не отбирает кандидатов по совпадению с числом ВОР.

`work_scope_graph` связывает участки, технологические слои, работы и материалы.
Идентичность участка включает SHA ВОР, лист, строку заголовка и адреса/тексты
разделов. Одинаковые названия в разных разделах дают только аналогию поиска.
Структурная принадлежность материала не доказывает формулу, расход или количество.
Граф ограниченного окружения передаётся агенту вместе с проверенными буквальными
основаниями соседних работ того же участка. Их область для текущей позиции
остаётся `unresolved`, пока агент не свяжет её с источниками.

Артефакты `work_scope_graph` и `scoped_project_facts` сохраняются неизменно в
существующей `analysis_artifacts`. Числовой факт содержит размерность, значение,
единицу, версию PDF, страницу, точную цитату, операнды и хеши источников.
`literal_state` отделён от `subject_state`: чтение числа не доказывает, к какой
работе оно относится. Ссылка и хеш реестра доступны в `coverage.fact_ledger`.
Исходный ответ модели и результаты локальных валидаторов остаются в истории.

Для новых проверок v6 незакрытый `evidence_work_plan_v1` ставит в outbox один
дополнительный агентный проход по открытым вопросам, максимум три обращения
к модели. Он использует сохранённые источники и подготовленный PDF, не запускает
OCR и не повторяется автоматически после технического сбоя. Первичный проход
сохраняет прежний предел: три обращения и одно узкое исправление выбора нормы,
если исправленная толщина впервые выявила новое условие. Таким образом, верхняя
граница двух проходов — семь обращений на позицию. Отключение дополнительного
прохода: `run.config.normative_evidence_followups=false`. Исторические ответы v5
и старше не запускают новый платный проход при установке обновления.

Сохранение ответа и намерения продолжить поиск выполняется одной транзакцией.
Повторная доставка не создаёт вторую платную попытку. Поиск норм идёт в очереди
`normative`, отдельно от сопоставления. Задачи одной позиции исполняются
последовательно; счётчики показывают позиции, а не число дополнительных задач.

Изменение доказанной геометрии родительской работы ставит локальную перепроверку
уже обработанных формально связанных материалов. Она заново проверяет исходный
ответ и закреплённые основания; модель, поиск и OCR не вызываются. Соседние строки
только со структурной принадлежностью не наследуют геометрию автоматически.
Снятие родительского подтверждения также меняет ревизию зависимости.

Подготовка всех PDF/OCR и выдача результатов порциями по 10 остаются прежними.
Для Docker включён `NORMATIVE_SQLITE_CACHE_DIR`: API и нормативный обработчик
используют общий том `normcache`. Исходный выпуск остаётся только для чтения;
копия SQLite создаётся атомарно и проверяется по SHA-256. При повторном запуске
сверяются метаданные оригинала и хеш локальной копии. Изменившийся оригинал либо
повреждённый кэш не дают подтверждения по непроверенным данным. Это устраняет
повторные случайные чтения SQLite через медленный Windows bind-mount. Кэш
наследует расположение данных Docker; при переносе стенда его можно восстановить
из нормативного корпуса. Вне Docker кэш выключен без этой переменной.

При плотном контексте v6 резервирует место для проектных источников. Полные
зарегистрированные нормативные выдержки могут переноситься из повторяющихся
метаданных в реестр: агент получает явный `read_source`, а не обрезанную цитату,
выданную за полный документ. Буквальные числовые шаблоны передаются целыми;
приоритет зависит от найденных конструкций и физических групп, не числа ВОР.
Размеры полей контекста сохраняются в `coverage.model_metadata_sizes`.
Нормативный обработчик завершает spans без синхронного сетевого `flush` после
каждой позиции: экспорт выполняет фоновый SDK, а телеметрия запросов остаётся
также в записи проверки. Недоступный экспортёр не задерживает выдачу результата.

Достижение целевых 52 подтверждений из 103 необходимо измерить отдельным живым
агентным прогоном; регрессионные тесты и граф связей не являются такой оценкой.

## Изменения версии 3

- Поиск по блокам документа с общей нормализацией русских слов и отдельным
  обнаружением ведомостей количеств. Каталог таблиц передаёт строки итогов;
  агент может читать выбранные row_ids вместо первых четырёх строк.
- Поисковые выдержки отделены от полного реестра источников. Точное чтение
  получает приоритет, короткие страницы сохраняются целиком; старые источники
  доступны через read_source. Размер окна ограничен, данные не исчезают после
  40 результатов. ID ячейки включает версию PDF, страницу и таблицу.
- Обязательное обнаружение таблиц перед окончательным «количество не найдено».
  Незавершённый поиск при исчерпании бюджета является техническим состоянием.
- Для числовых предложений quantity/thickness нужны scope_state и scope_quote.
  Число, цитата и область должны принадлежать одному источнику; другой слой и
  явно неустановленная область не становятся числовым расхождением.
- OCR v4 исправляет границы координат повёрнутых листов и читает строки в
  распознанной системе координат. Физическая сетка ищется внутри рамки чертежа;
  небольшие разрывы пересечений замыкаются без заполнения пустых ячеек.
- Сборочный --warm материализует лениво загружаемые веса кириллического OCR.
  Числовая OCR-ячейка может получить numeric_verified только при совпадении
  RapidOCR и Tesseract в той же физической области с порогами уверенности.
  Сомнительные ячейки остаются неподтверждёнными.
- Расчёт суммы сохраняет отдельные PDF-прямоугольники каждого операнда.
- normative_corpora содержит новые подготовленные снимки по закреплённой
  версии PDF. prepare_run публикует их после CPU-подготовки; refresh_document
  позволяет локально обновить до трёх ведомостей старого документа без новой
  проверки ВОР, платной модели и изменения исходных результатов.

Ниже сохранено описание исходной организации второго слоя.

Новый этап запускается существующим outbox после сопоставления каждой позиции,
в отдельной очереди `normative`. Он не меняет сохранённый результат сопоставления.

## Причины изменения

В исследованном прогоне 58cfba95-1e05-436f-9bf6-291f10b404e6 из 87 исходных
нормативных проверок 47 записали ValueError до запроса провайдеру, 16 — таймаут.
Старый запрос включал полный граф matching_checks с исходными фактами, хотя
провайдерный адаптер ограничивал JSON 60000 символами. Техническая ошибка
сохранялась как обычная неопределённость инженерной проверки. Предыдущие
исправления отдельных дорожных случаев не исправляли этот механизм.

## Последовательность

1. Загружается проверенный по SHA снимок PageTextIndex из задания позиции.
   Это тот же текст, таблицы, страницы с ошибками и список ожидающего OCR,
   которые подготовил CPU-этап сопоставления. PDF повторно не разбирается.
   Поздние снимки того же PDF могут закрыть OCR-пробелы ранней позиции;
   недостающая таблица читается из проверенной по SHA страницы снимка соседней
   позиции. Другие PDF и версии в такое объединение не включаются.
   Для старых ручных проверок без снимка сохранён прежний источник страниц.
2. Строится ограниченный контекст: работа, формула и зависимости, связанные
   строки ВОР, идентификаторы/состояния требований, выдержки ПД и нормативов.
   Сырые массивы OCR/facts из matching_checks не передаются повторно.
3. Агент возвращает ответ либо до четырёх запросов инструментов за шаг:
   поиск ПД по смысловым словам, чтение страницы с offset, чтение четырёх строк
   таблицы с заголовками, поиск норм, сложение конкретных числовых ячеек.
   Максимум три обращения к модели, без скрытых повторов провайдера.
4. Инструменты принимают только закреплённый корпус и реальные ID. Суммы
   вычисляются Decimal; повторные/неизвестные ячейки, неустановленная единица,
   сомнительные и OCR-ячейки не получают расчётного подтверждения.
   Верная арифметика сама по себе не устанавливает инженерную применимость.
5. Ссылки, цитаты, величины, единицы, формулы и обязательные аспекты проверяются
   существующими валидаторами. Неподтверждённый коэффициент остаётся вопросом,
   даже если количество родительской работы найдено.
6. Результат содержит pipeline_version, execution_state, coverage и evidence_trace.
   История запросов к инструментам сохраняется в БД вместе с ответом, usage —
   в telemetry. Техническая ошибка публикуется как «Проверка не выполнена».

При поиске поправок между таблицами используются определения из `norms.title`
закреплённого корпуса. Буквальная ссылка, шаг и направление проверяются отдельно;
сам факт найденного кандидата не подтверждает его применимость.

Подбор страниц сопоставления больше не повышает оценку за совпадение ожидаемого
объёма ВОР. При выборе фрагмента учитывается наличие числовых данных, включая
отличающиеся величины. Явные операнды формулы сохраняют контекстный приоритет.

Новые ответы не проходят старое локальное исправление сохранённых ответов
по частным признакам ЩПС. Исторические проверки не переписываются при установке.

## Проверки и границы

### Несколько явно связанных PDF

При `AUDIT_MULTI_PDF_CONTEXT=1` предварительная привязка и подготовка принимают
несколько точных ссылок одной позиции. Сопоставление сохраняет первый PDF как
основной. Нормативный агент дополнительно получает все явно связанные PDF из
`supporting_documents`: каждый имеет собственный закреплённый `version_id` и
полный подготовленный снимок. Поиск идёт по всем этим документам; чтение страницы
или таблицы дополнительного документа требует `document_version_id`. Страницы
не перенумеровываются. Неизвестный документ, неполный снимок и сложение ячеек
разных PDF отклоняются. Автоматического OCR на нормативном этапе нет.

По умолчанию флаг выключен: старый путь продолжает явно отклонять неоднозначную
привязку. Локальный комплект из десяти ВОР использует основной ПД и ПОС с этим
флагом. Это поддержка чтения нескольких источников на нормативном этапе,
а не объединение их номеров страниц в исходном сопоставлении.

Уточнение политики коэффициентов: явно подписанные значения уплотнения,
разрыхления и расхода считаются предоставленными сметчиками. Отсутствие их
нормативной базы само по себе не ошибка ВОР. Происхождение сохраняется отдельно
от независимого нормативного подтверждения. Проверка арифметики и доказанных
противоречий не отключается; к неподписанным числам формулы это правило не
применяется.

### Обратная связь инженера: коэффициент и контрольный запуск

Контрольный пример, выбранный пользователем:
http://192.168.30.183:3000/audits/edf32584-4da6-4767-9615-808ca92c1e17.
По обратной связи пользователя, в нём шесть подтверждённых позиций и верно
выявленные расхождения. Это исходный контрольный пример, а не результат нового
прогона v6. При регрессии сравнивать основания и реальные расхождения, а не
только количество зелёных статусов.

Для явно подписанного в ВОР коэффициента уплотнения 1,26 уточнено происхождение:
его предоставляют сметчики по своей нормативной базе. Название источника пока
неизвестно и требует поиска. `value_basis.kind=estimator_provided` сохраняется
в трассе принятого коэффициента и передаётся агенту как
`estimator_coefficient_basis`. Это поясняет уже существующее пользовательское
допущение и не расширяет условия автоматического подтверждения. Число в ВОР
само по себе не доказывает нормативную применимость; значение другого
коэффициента, марка, участок, геометрия, арифметика и противоречия проверяются
независимо. Независимая нормативная проверка этого значения не заявляется до
нахождения документа и проверки его условий.

Найден кандидат для дальнейшей проверки: СП 78.13330.2012, п. 10.2,
[копия с изменением № 1 на mos.ru, физическая страница 30](https://www.mos.ru/upload/documents/files/9966/SP78133302012.pdf#page=30).
В нём предусмотрен ориентировочный диапазон 1,25–1,3 для определённых смесей
и щебня при указанных характеристиках материала; фактический коэффициент
определяется пробной укаткой. Попадание 1,26 в диапазон не устанавливает
источник конкретного значения сметчиков, применимость редакции или выполнение
условий проекта. Эта ссылка пока не добавляет подтверждённых карточек.

контекста учитывается каталог накопленных источников. Неизвестные обязательные
данные по-прежнему не удаляются ради прохождения лимита.

Последующие исправления поиска и воспроизводимости:

Полная локальная выгрузка контрольного запуска подтверждает: 103 результата,
6 `confirmed` (индексы 0, 2, 37, 39, 42, 59), 94 `needs_facts`,
3 `possible_mismatch`. Исходные результаты при выгрузке не изменялись.
По последующему уточнению пользователя основание сметчиков относится ко всем
явно подписанным коэффициентам уплотнения, разрыхления и расхода; это не
разрешает считать произвольные числа формулы коэффициентами.

- Явные обозначения свойств материала ищутся отдельно в названном стандарте.
  Буквальное наличие М800/К90/М1 проверяется в найденном тексте; совпадение
  одного номера ГОСТ не считается найденной характеристикой. Источники
  чередуются между свойствами в пределах четырёх дополнительных кандидатов.
  Это навигация для модели, без автоматического вывода об эквивалентности.
- Первый обработчик атомарно закрепляет `normative_kb_pin` за запуском;
  остальные используют этот же выпуск. Ключ кэша учитывает закреплённый
  выпуск. Продолжение поиска сохраняет привязку исходного ответа; конфликт
  с уже закреплённым выпуском останавливает обращение к модели.
- Ошибки транспорта расходуют общий лимит запросов, но не превращают первый
  успешный ответ в финальную проверку: при отсутствии успешного плана этап
  навигации сохраняется. Невыполненное чтение источника не считается выполненным.
- Повторяющийся навигационный каталог таблиц сокращается при нехватке контекста.
  Выбранные ячейки, суммы, обязательные требования и архив источников сохраняются.
  Старое пояснение вывода может быть опущено, но его claim, state и ссылки
  сохраняются. Короткие нормативные цитаты не заменяются более длинными
  служебными описаниями. Перестановка неизменных прямоугольников подсветки
  не считается конфликтом; содержимое замороженного источника сохраняется.
- По просьбе пользователя удалён строгий маршрут DeepInfra: RouterAI получает
  чистый идентификатор DeepSeek и автоматически выбирает upstream. API и два
  LLM-обработчика основного стенда пересозданы только для применения окружения;
  новая версия кода на основной стенд этим действием не установлена.

После дополнительного разрешения журнал доведён до 99 запросов суммарно
(ещё 30 от отметки 69). На автоматическом маршруте получены успешные ответы,
без 503 в этом контрольном прогоне. Повторно обработаны позиции 0–8;
позиция 9 повторно через модель не запускалась из-за предела бюджета.
Новых полностью подтверждённых позиций нет: первые восемь сохраняют
обязательные числовые основания, а открытые вопросы техники, свойств и
применимости нормы остаются отдельными аспектами. Позиция 8 выявляет ещё одну
задачу контракта: площадь-операнд нельзя сравнивать как готовую массу работы.
Отсутствие подтверждённого перевода расхода в массу требует поиска основания,
а не автоматического вывода о расхождении единиц ПД и ВОР.

### Входы и выход расчётной позиции

В версии числового контракта 10 явно заданный расход в кг/м² или л/м²
и ограниченная формула вида «площадь × расход / 1000» образуют контракт
`project_quantity_contract`. Поиск таблиц получает единицу входа м², а
измеритель нормативной работы остаётся в исходной единице позиции.
Названия связанных конструкций уточняют поиск; совпадение ожидаемого числа
не используется для выбора таблицы или участка.

`input:area` — самостоятельная карточка площади-основания. Цитата, качество
распознавания, размерность, участок и слой проходят прежние проверки.
`quantity` — конечное количество работы или родительской работы материала.
Найденная площадь не записывается в эту карточку как масса. Она не может
выполнить нормативное условие на итоговое количество. Если ПД прямо задаёт
массу, её обычная проверка сохраняется; реальные расхождения массы и входной
площади не снимаются.

В реестре фактов площадь сохраняется с `quantity_role=calculation_input`.
Подтверждение такого входа не подтверждает результат формулы, применимость
расхода, плотность или всю позицию. Для старого ответа без отдельного аспекта
входа сохраняются прежние сомнения модели о принадлежности площади;
перепривязка к новому участку автоматически не производится.

Локальный повтор на сохранённом ответе позиции 8 сохранил 431,611 м² как
вход и оставил массу неподтверждённой вместо сравнения м² с тоннами.
Новых запросов модели и OCR при этой проверке не было. Это исправление
контракта, а не доказательство достижения целевого числа подтверждений.

Числовая регрессия выполнена по всем 103 сохранённым ответам контрольного
запуска без модели и OCR. Контракт выделил входную площадь в 20 позициях
(работах и связанных материалах). Количество подтверждённых числовых карточек
осталось 272; три прежних числовых расхождения сохранены. Добавились 20
отдельных проверок входа. Эти подсчёты не являются числом полностью
подтверждённых позиций: исходные инженерные выводы и записи БД не менялись.

Тесты используют синтетическую модель и изолированную PostgreSQL. Есть сценарий
«таблица → две ячейки → серверная сумма → числовая карточка → итог ОК», отказ
от выдуманных ссылок и ошибочных единиц, неполный OCR, исчерпание бюджета и
слишком большой исходный граф фактов. Это не live-оценка качества модели.

Таблицы доступны в той мере, в какой их подготовил CPU-этап. Агент видит
покрытие; он не выполняет неограниченный OCR в своей очереди. Если нужный скан
не подготовлен, требуются дальнейшее извлечение и повтор нормативного этапа.
Лексический поиск не заменён векторным. Неподтверждённая редакция нормативов
и инженерная применимость остаются явными ограничениями результата.

Для DeepSeek через RouterAI задан reasoning_effort=low. Бюджет ответа
нормативного этапа — 8192 токена (включая рассуждения), таймаут — 60 секунд
на запрос. Максимум три запроса агента сохраняется. Усечение по length
фиксируется до разбора JSON как технический сбой, usage сохраняется и платный
повтор автоматически не выполняется. execution_state передаётся в список
результатов: сбой не подменяется ручной инженерной проверкой.

### Справочная марка и обязательная функция машины

Сохранённое сопоставление нормализуется тем же ограниченным парсером, что и
новый запрос. Если полная фраза разделяется на функцию машины и её справочную
марку, `attribute:comment:equipment_names` не становится обязательным повторно
из-за старого сопоставления или ответа модели. Функция сохраняется отдельным
обязательным требованием. Мощность, масса, ширина, запреты и неизвестные
дополнительные условия этим правилом не снимаются.

Смешанный ответ разделяется по идентификаторам требований: справочная марка
не может подтвердить функцию, применимость нормы или числовую карточку.
Отрицательный вывод не переводится в справочный даже после понижения его
статуса проверкой ссылок. Исходный вывод и привязка к позиции сохраняются в
трассе. Само исправление классификации не подтверждает позицию.

### Навигация дополнительного поиска

Первый проход читает конструкцию и итоги проектных таблиц. Дополнительный
проход получает другой стартовый запрос: целевые чтения по открытым
`evidence_followup.actions`. Если осталась только нормативная применимость,
свойство материала или функция машины, повторный поиск площадей не задаётся
приоритетом. Открытый числовой аспект или новое противоречие источников
по-прежнему требует проверки проектных оснований.

При достаточных сохранённых источниках агент может сразу предложить итог;
он проходит те же проверки ссылок, чисел и области применения. Лимиты
запросов и запрет повторного OCR не изменяются. Тест реального агентного цикла
с синтетическим ответом проверяет целевое чтение и вызов валидатора, но
не доказывает качество будущего ответа DeepSeek.

### Независимые примечания и предмет доказательства

Новая физическая заметка, начинающаяся с самостоятельного действия или
технического требования, отделяется от предшествующего свойства. Например,
«нормировать в два слоя» не включает следующую строку о мощности бульдозера.
Нормативная инструкция имеет собственный семантический тип и направляется
в поиск нормативных условий. Для совместимости сохранён её старый непрозрачный
claim ID; агент получает точные label/expected_text и тип задания.

Отделённая заметка сохраняется обязательным условием, в том числе при
нормализации старого сопоставления. Прежние проверки источников мощности
и нормативного условия сохранены. Класс/функция машины получает отдельное
задание на буквальную классификацию и связь с применимым способом работ;
это не автоматически положительный вывод о конкретном экземпляре.

Локальный разбор всех 103 сохранённых позиций выявил такую структуру в
12 позициях на разных участках. Вердикты БД не менялись, модель и OCR
для этого подсчёта не вызывались.

Контроль после исправления: первая позиция запуска
`da5da472-c10b-4558-8e92-736e223c094a` получила `confirmed` в агентном
проходе (исходный ответ сохранён в проверке
`641682f1-ed91-457c-bb07-11d43cd7692a`). Модель подтвердила применимость
нормы и функцию оборудования. Условие о слоях проверено по буквальному
нормативному основанию и подтверждённой толщине ПД общим валидатором.
Состояние не исправлялось вручную. Сохранённые основания дважды прошли
повторную проверку текущими валидаторами с запретом обращений к модели/OCR;
оба раза итог остался `confirmed`.

В последнем согласованном контрольном цикле использованы все 12 запросов:
первые три позиции — 7, свежая первая позиция — 2 и её целевой дополнительный
проход — 3. После последней смены парсера остальные позиции не проверены
заново. Это подтверждение одного воспроизводимо используемого результата,
а не достижение 52/103 или оценка всего набора на одной версии алгоритма.

### Проверка повторяемости новых ответов модели

Повторная локальная валидация сохранённого ответа не доказывает стабильность
нового модельного анализа. Для независимого эксперимента используется
конфигурация запуска `normative_fresh_model: true`: нормативный этап не читает
готовый ответ из кэша и не подменяет новый ответ первым сохранённым результатом.
Подготовленные страницы, OCR и таблицы остаются доступными. Связанные факты
могут использоваться внутри одного агентного запуска, но независимый повтор
создаётся отдельным запуском без предыдущих нормативных ответов.

Команда `python -m scripts.preflight_agent_benchmark --matching-run <UUID>
--prepared-run <UUID> --output <new-manifest.json>` проверяет входы без модели,
OCR и записи в БД. Запуски должны относиться к одной версии ВОР, тем же строкам
и закреплённым PDF. Проверяются все сопоставления, хеши исходного PDF и его
представления, снимки, завершённость подготовки и связи работ. Хеш снимка может
соответствовать сериализации PyMuPDF; это разрешено только после вычисления
такого представления из проверенных исходных байтов, а не по совпадению имени.

Для локальных 103 позиций проверены все сохранённые сопоставления контрольного
запуска и подготовка из 99 страниц/114 таблиц другого запуска той же версии
ВОР/ПД. Манифест фиксирует оба происхождения и не утверждает инженерную
корректность или достижение порога 52 подтверждений.

### Сохранённые единицы таблиц и контроль нового комплекта 437 строк

В запуске `f543e0b5-26dc-4264-ac55-386e47972798` полная подготовка
364 страниц завершилась, но это не означало проверенности каждой ячейки.
Среди 86 сохранённых нормативных ответов 84 технически завершены, два имели
технический сбой; главный массовый блокер находился в доказательствах
количества и единиц, а не в отказах провайдера модели.

Проверка надстрочных единиц ошибочно отвергала отчётливо поднятую двойку,
почти равную по высоте строчной «м». Теперь такой случай требует близости
символов и верхнего положения нижней границы степени. Пороги уверенности
OCR не снижены. Обычная строковая цифра, удалённая цифра и конфликт чтений
не принимаются.

`pdf_saved_evidence.replay_unit_proofs` повторно проверяет сохранённые
чтения физических заголовков, возвращая производное представление таблицы.
Исходный снимок не меняется, PDF не открывается, OCR не вызывается.
Привязка к заголовку, столбцу, рамке и двум согласованным чтениям проходит
тот же валидатор. Числовые ячейки этот механизм не подтверждает.
Исправленные единицы используются и при поиске кандидатов, и при чтении
таблицы агентом. На страницах 108–110 восстановлены единицы 39 столбцов.
Исчерпание лимита числа заголовков теперь явно сохраняет отложенные ID,
а не выглядит как завершённая проверка заголовков.

Резервный `matching:verdict` предоставляется агенту только когда он входит
в реальный план требований. Неопределённость расхода дочернего материала
должна оставаться в `related:<index>:rate`, отдельно от проверки работы.
Неизвестные требования и реальные противоречия не переводятся автоматически
в подтверждённые. Версия агентного конвейера повышена до 7.

Две контрольные позиции проверены штатным агентом на сохранённых данных:
индекс 14 (ВОР, строка 34; бортовой камень, 116 м) получил `confirmed`
за два запроса, проверка `a1c1ef15-fe45-46b7-9302-9bf08b262bb5`.
Индекс 0 остался `needs_facts` за три запроса: число и толщина ещё не прошли
валидацию. Ни страницы, ни правильные ответы в контрольные запросы
вручную не задавались. Снимки подготовки остались прежними. Общий запуск
остановлен после 107 сопоставленных строк; весь комплект после исправления
не перепроверен. Один успешный контроль не доказывает качество всех 437 строк.
