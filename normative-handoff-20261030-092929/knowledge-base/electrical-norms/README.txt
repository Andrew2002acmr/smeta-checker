ЛОКАЛЬНАЯ НОРМАТИВНАЯ БАЗА ЗНАНИЙ ДЛЯ ИНЖЕНЕРОВ ПО ЭЛЕКТРИКЕ
Сборка от 26.10.2026. Назначение: подключение к существующей системе анализа ПД и ВОР.

1. ЧТО СОБРАНО

24 исходных нормативных PDF, 2511 физических страниц.
ГЭСН: 15 сборников. Из них 8 разобраны в таблицы/позиции, 7 смежных
строительных сборников доступны как исходный текст и текстовые пункты.
Основные: ГЭСН33, ГЭСНм08, ГЭСНп01, ГЭСНр67.
Смежные: ГЭСН34, ГЭСНм10, ГЭСНм11, ГЭСНп02.
Строительные: ГЭСН01, 05, 06, 07, 09, 30, 32.
Проектные нормы: СП 52.13330.2016, СП 76.13330.2016, СП 98.13330.2018;
ГОСТ 21.110-2013, ГОСТ 21.607-2014, ГОСТ 21.613-2014,
ГОСТ Р 21.101-2026, ГОСТ Р 55706-2023; сборник глав ПУЭ 6 и 7 изданий.

Результат извлечения: 6606 пунктов, 935 таблиц ГЭСН, 5634 позиции,
51973 ресурсные ячейки (включая пустые и значения «П»), 15696 поисковых
фрагментов. Это количество извлеченных записей, а не количество
инженерно подтвержденных требований.

12 проверенных по тексту правил-подсказок: высота для монтажа и ПНР,
повторная ПНР, отдельно учитываемые работы, возможное повторное включение
подключения проводников и исключение контактных сетей из области СП 76.
Правила возвращают условия и ссылки, не применяют коэффициенты автоматически.

2. ГДЕ ДАННЫЕ

CURRENT.json — указатель на текущий выпуск. Читать его первым.
releases/<выпуск>/knowledge.sqlite — основная база SQLite с полнотекстовым FTS5.
releases/<выпуск>/exports/*.jsonl — переносимые записи для вашей системы/RAG.
releases/<выпуск>/manifest.json — состав выпуска и происхождение документов.
releases/<выпуск>/quality-report.json — технические проверки и ограничения.
blobs/<префикс>/<sha256>.pdf — копии оригиналов с контролем SHA-256.
inputs/ — рабочие скачанные источники; acquisition.json — журнал получения.
examples/ — SQL, JSON с фактами объекта, пример подключения из Python.
ontology.json — темы и синонимы для маршрутизации поиска.

Для переноса базы сохраняйте CURRENT.json, выбранный release и blobs.
Копии нормативных источников расположены локально. Проектные документы
с K: и из папки «Мост Автозаводская» в этот нормативный корпус не включены.

3. КАК ХРАНИТЬ И ПОДКЛЮЧАТЬ

SQLite + JSONL + оригиналы PDF — основной локальный формат. Векторный индекс
пока не создавался. При необходимости его следует строить из chunks.jsonl
как производный индекс, сохраняя id фрагмента, source_id и SHA-256 источника.
Расчетные числа и условия коэффициентов хранить в структурных таблицах;
векторный поиск сам по себе не проверяет единицы, диапазоны и применимость.
При многопользовательской эксплуатации те же сущности можно перенести в
PostgreSQL, сохранив исходные id и ссылки. Для текущего локального этапа
дополнительный сервер базы данных не требуется.

Код находится в D:\VOR\vorcheck\normative.py и normative_rules.py.
Запускать из D:\VOR:

.venv\Scripts\python.exe -m vorcheck.normative status
.venv\Scripts\python.exe -m vorcheck.normative search "заземление" --kind PUE --limit 5
.venv\Scripts\python.exe -m vorcheck.normative norm ГЭСНм 08-02-148-02
.venv\Scripts\python.exe -m vorcheck.normative evaluate knowledge-base\electrical-norms\examples\montage-height.json
.venv\Scripts\python.exe -m unittest tests.test_normative -v
.venv\Scripts\python.exe -m scripts.validate_electrical_norms

Для существующей системы: открыть SQLite только для чтения; либо импортировать
JSONL. Пример SQL в examples/query.sql. Пример Python в examples/integrate.py.
HTTP-сервер и новый интерфейс для использования этой базы не нужны.

Предлагаемая последовательность подключения:
а) извлечь из ПД/ВОР вид системы, стадию, дату проекта, способ прокладки,
   напряжение, массу кабеля на метр, условия высоты, единицы и количества;
б) найти кандидатов по тексту и тематике; ограничить документы по области
   применения, дате и подтвержденной редакции;
в) сопоставить код, измеритель, состав и исключения конкретной нормы;
г) оценить правила с трехзначной логикой: применимо / неприменимо / нужны факты;
д) проверить взаимосвязи, возможные дубли и отсутствующие работы с учетом ПД;
е) выдавать инженеру варианты с условиями выбора и цитатами. Отсутствие позиции
   в ВОР без доказанной необходимости по ПД не объявлять нарушением.

4. КОНТРАКТ ЗАПИСЕЙ

sources: документ, вид, роль, обозначение, SHA-256, путь оригинала, метаданные
редакции и происхождения. source_key — логическое имя, id — конкретный снимок.
pages: исходный и очищенный текст физической страницы.
clauses: текст пункта и ссылки; автоматическая сегментация может захватывать
таблицы/подпункты. Перед нормативным выводом читать контекст исходной страницы.
norm_tables: название, измеритель, состав работ в исходной области действия.
norms: код, название, измеритель и атрибуты варианта нормы.
resources: ячейка ресурса конкретной нормы, количество, единица, статус.
rules: область, условия, результат, ссылки и статус проверки.
relations: явно подтвержденные связи между сущностями.
chunks/search_fts: поисковые фрагменты и лексический индекс.
gaps/review_queue: недостающее покрытие и ошибки/неоднозначности извлечения.

В SQLite сложные поля имеют суффикс _json. В JSONL они уже декодированы.
Количество хранится десятичной строкой, а не двоичным float.
quantity_kind: numeric — число; blank — пустая ячейка; by_project — «П»;
dash — тире; unparsed — нераспознанное значение. NULL не равен нулю.
unit.scale=100 и unit.unit=м означает нормирование на 100 м, а не на 1 м.
citations: source_id, physical_page (с 1), bbox при наличии геометрии,
coordinate_system=pdf_points_bottom_left, метод извлечения.
Физический номер PDF может отличаться от печатного номера листа.

Статусы extracted_* означают автоматическое извлечение для поиска/проверки.
definition_reviewed означает сверенное определение позиции, source_reviewed —
сверенную ячейку. Эти статусы не подтверждают актуальность редакции документа.
source_checked_requires_edition_confirmation у правил требует проверки редакции.
usable_for_calculation всегда false до внешнего подтверждения редакции
и применимости. Правила не перемножают коэффициенты и не меняют смету.

5. ЧТО ПРОВЕРЕНО И ЧТО ОСТАЛОСЬ

Пройдены 8 тестов: границы высоты, недостающие факты, разделение монтажа/ПНР,
пустые ресурсные колонки, точность десятичных чисел, масштаб единицы,
поиск по всем четырем видам источников и целостность SQLite.
Аудит проверяет хеши всех PDF, номера страниц ссылок и полноту JSONL.

По оригиналу физической страницы 85 ГЭСНм08 сверены определения 9 вариантов
08-02-148 и 50 ресурсных ячеек первых 5 вариантов. Остальная числовая
масса остается результатом автоматического извлечения, требующим проверки.
786 ячеек не разобраны однозначно; 1829 измерителей требуют уточнения.
ГЭСНп01/02: названия, пункты и страницы извлечены; таблицы затрат труда
пока не преобразованы в ресурсные ячейки. Считать их нулевыми нельзя.
Четыре малотекстовые страницы отмечены для визуальной проверки/OCR.

Полнота актуальных изменений не подтверждена: сверить изменения СП 52,
поправки ГОСТ 21.607 и 21.110 и остальные редакции по карточкам источников.
Смешанный сборник ПУЭ требует подтверждения издания и приказа каждой главы.
ГОСТ Р 50571.5.54 и ГОСТ Р 50571.16 пока включены в список пробелов, а не
в доступные тексты. Для анализа старой ПД потребуется редакция на дату проекта;
сейчас многолетний архив замененных редакций не собран.
Таблицы проектных СП/ГОСТ доступны в тексте страниц, но не нормализованы
в универсальные числовые требования. Проверка инженерных расчетов по ним
потребует отдельной структуризации и верификации соответствующих таблиц.

Это первая локальная база для поиска и разработки интеграции. Полная
автоматическая экспертиза ПД/ВОР и подтверждение всех числовых данных
в выполненный результат не входят и не выдаются за готовую функцию.

6. ОБНОВЛЕНИЕ

Источники перечислены в D:\VOR\configs\electrical-normative-sources.json.
Скачать открытые источники: python -m scripts.fetch_electrical_norms.
Построить новый выпуск: python -m vorcheck.normative build.
После сборки обязательно выполнить тесты и validate_electrical_norms.
Сборка создает новый каталог и переключает CURRENT.json после проверки
целостности SQLite. Предыдущие выпуски и исходные снимки сохраняются.
Для отката можно указать предыдущий выпуск через CURRENT.json.
Файл сборника в inputs не обновляется скачиванием, если уже находится в кеше:
новую редакцию следует загружать с отдельным ключом источника и метаданными,
чтобы не подменять старый документ без явного учета версии.
