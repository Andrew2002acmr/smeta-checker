НОРМАТИВНЫЕ БАЗЫ ДЛЯ ИНТЕГРАЦИИ ПД / ВОР

Это переносимый снимок двух нормативных корпусов, а не дамп PostgreSQL приложения.
Включены дорожная база и база по электрике, оригиналы PDF, SQLite, JSONL и SQL.
ПД объекта, ВОР, пользователи, пароли, ключи API и результаты проверок приложения
в архив не включены. Оригинальные базы на компьютере отправителя не менялись.

БЫСТРЫЙ СТАРТ
1. Распаковать ZIP целиком в отдельный каталог. Windows и Linux поддерживаются.
   Не заменять файлы уже работающей базы без проверки: можно подключить архив
   из нового пути. Распакованный объём около 600 МБ; точный состав — PACKAGE.json.
2. Из корня распакованного пакета выполнить (Python 3.11+ с SQLite FTS5):
     python verify.py
     python integration/example.py
   В Windows вместо python можно использовать py -3.11.
   Дополнительные pip-пакеты для этих команд не нужны, интернет не требуется.
3. Готовые knowledge.sqlite можно сразу читать. Ничего восстанавливать не нужно.
   Для выбора выпуска сначала читать CURRENT.json, затем его поле database.
   PDF разрешать относительно корня соответствующего корпуса по sources.blob_path.

КАК ПОДКЛЮЧИТЬ К НАШЕМУ ПРОЕКТУ smeta-checker
В текущем коде существуют переменные:
  NORMATIVE_KB_ROOT — путь к knowledge-base/electrical-norms внутри процесса;
  NORMATIVE_ROAD_KB_ROOT — путь к knowledge-base/road-norms внутри процесса.
Для Compose с существующим compose.local.yaml задайте в своём env-файле:
  NORMATIVE_KB_HOST_ROOT=D:/путь-к-пакету/knowledge-base/electrical-norms
  NORMATIVE_ROAD_KB_HOST_ROOT=D:/путь-к-пакету/knowledge-base/road-norms
На Ubuntu пример: /srv/normative-handoff/knowledge-base/road-norms.
Монтировать read_only в API и worker-normative. Пример отдельного override:
  integration/compose.normative.example.yaml
Изменения подключения применяются к сервисам, использующим нормативку; пакет
сам ничего не запускает, не перезапускает и не обращается к внешней модели.
Для старой ветки без нормативного слоя сначала потребуется соответствующий код.
Исходный автономный адаптер из проекта приложен: integration/normative_corpus.py.

ПОДКЛЮЧЕНИЕ К ДРУГОЙ СИСТЕМЕ
Минимальный клиент: integration/kb_client.py; пример: integration/example.py.
Можно читать SQLite только для чтения или импортировать exports/*.jsonl в свою БД.
Основные таблицы, единицы, статусы и цитаты описаны в integration/CONTRACT.txt.
Поиск FTS5 лексический, векторный индекс и embeddings не приложены.
Совпадение текста выдаёт кандидата, а не подтверждает инженерную применимость.

SQL-ДАМПЫ
sql-dumps/road-norms.sql.gz и electrical-norms.sql.gz — SQLite SQL, НЕ PostgreSQL.
Они содержат схему, данные и FTS5 без внутренних shadow-таблиц.
Восстановление в НОВЫЙ файл (существующий файл никогда не перезаписывается):
  python restore_sqlite.py road-norms D:/norms-test/road-restored.sqlite
  python restore_sqlite.py electrical-norms D:/norms-test/electrical-restored.sqlite
В Linux последний аргумент, например, /tmp/road-restored.sqlite.
Это запасной способ; для обычного подключения достаточно готовых SQLite.
Для PostgreSQL предпочтителен импорт JSONL с сохранением строковых ID, связей,
десятичных строк и отдельным индексом поиска. SQLite SQL в psql не выполнять.
Alembic-ревизии приложения эти корпуса не создают; stamp/reset не требуется.

ДОПОЛНЕНИЯ ПОСЛЕДНИХ АУДИТОВ
supplemental-documents/ — дополнительные тексты/копии нормативов, включая
приказ 69/пр от 07.02.2025, изменения СП и справочную редакцию ГЭСН27.
ОНИ ЕЩЁ НЕ ВКЛЮЧЕНЫ В SQLITE / FTS / JSONL. Это явно отражено в INDEX.json.
Не подменять ими документы текущего выпуска молча. Новую редакцию добавлять
отдельным source_id с SHA-256, затем пересобирать новый выпуск и проверять ссылки.
Среди дополнений есть старая копия приложения ГЭСН27: маркирована как outdated.
У приказов и сводных текстов разная область/дата; актуальность требует сверки.
Нормативные выводы аудита без проектных документов: integration/ROAD-NOTES.txt.

ПРОИСХОЖДЕНИЕ И ОГРАНИЧЕНИЯ
В источниках сохранены исходные метаданные, в том числе исторические абсолютные
пути компьютера отправителя. Они служат происхождению, а не загрузке PDF.
Для работы на другом ПК используют относительные CURRENT.database и blob_path.
README электрической базы сохранён как историческая инструкция; его команды
сборки требуют исходного рабочего проекта, в отличие от автономных команд выше.
project-bindings.json с UUID локального проекта в перенос не включён. Привязки
к проектам коллеги нужно создать в его приложении, а не переносить чужие UUID.
Полнота редакций и числовая корректность автоматического извлечения не заверены
одной технической проверкой. Условия/коэффициенты не применять автоматически.

КОНТРОЛЬ
SHA256SUMS — SHA-256 каждого файла, кроме самого списка.
PACKAGE.json — выпуски, состав, таблицы, страницы и параметры экспорта.
verify.py проверяет хеши, источники PDF, SQLite, внешние ключи, JSONL и FTS.
Архив дополнительно проверен после распаковки в другой путь; оба SQL-дампа
проверены восстановлением и сравнением логических данных с исходным снимком.
